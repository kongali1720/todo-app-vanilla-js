# Governance

Welcome to the governance documentation for **todo-app-vanilla-js**.

This document describes how the project is maintained, how decisions are made, and how contributors can participate in the project's development.

---

# Project Vision

The goal of this project is to provide a simple, clean, and educational **Vanilla JavaScript To-Do List** application that is easy to understand, extend, and maintain.

The project prioritizes:

- Simplicity
- Readability
- Accessibility
- Performance
- Community contributions

# Contributions

Everyone is welcome to contribute.

Please read:

- CONTRIBUTING.md
- CODE_OF_CONDUCT.md
- SECURITY.md

before submitting a Pull Request.

---

# Pull Request Review

Every Pull Request should:

- Solve one problem at a time.
- Follow the project's coding style.
- Include clear commit messages.
- Avoid unnecessary complexity.
- Update documentation when needed.

Pull Requests may be reviewed before merging.

---

# Releases

Project releases follow Semantic Versioning.

Format:

MAJOR.MINOR.PATCH

Examples:

- 1.0.0
- 1.1.0
- 1.2.3
- 2.0.0

Release notes will be published in:

- CHANGELOG.md
- GitHub Releases

---

# Issue Management

Issues are categorized into:

- Bug
- Feature Request
- Enhancement
- Documentation
- Question
- Security

Duplicate or inactive issues may be closed.

---

# Security

Security reports should follow the process described in:

SECURITY.md

Please avoid public disclosure of security vulnerabilities before they have been reviewed.

# Community Standards

Community members are expected to:

- Be respectful.
- Help others.
- Welcome newcomers.
- Provide constructive feedback.
- Maintain a friendly environment.

All participants are expected to follow the project's Code of Conduct.
